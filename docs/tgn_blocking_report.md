# CORTGN 阶段实验报告

- 日期：2026-09-19
- 仓库：https://github.com/ImmortalWatcher/CORTGN
- 对应代码：`scripts/blocking_baseline.py`、`scripts/tgn_blocking.py`
- 对应数字：`scripts/blocking_baseline_results.json`、`scripts/tgn_blocking_results.json`

本报告记录第一轮**时序图谣言级联动态阻断**实验：数据盘点、非学习基线，以及最小 TGN 是否超过观察出度。不是 DAMMFND 复现报告。论文若用到 DAMMFND，按文献引用即可。

## 1. 要回答的问题

突发舆情已经发出之后，能不能在观察窗口 `t0` 内，从**已出现的非根节点**里选出 `k` 个账号/转发，使后续真实传播少走一段。

评价用实现树上的反事实切除，而不是再训一个生成式传播模型：

- 时刻 0 = 根帖时间。
- 候选集 = `t0` 前已出现、且不是根的节点。根帖视为已发出；若允许删源，任何策略都会变成 100%。
- 阻断节点 `v`：`t0` 之后落在 `v` 子树上的节点视为不再发生。
- 指标 `block_rate` = 被切掉的未来节点数 / 全部未来节点数。
- 主看谣言树（`events.txt` 中 `label=1`）。

这是离线反事实，不是平台封禁日志。数据是树，没有「多路听到」：切掉 A 后，B 不会改从别人转发。

## 2. 数据：weibo22

来源是 Ma 等人常用的微博谣言级联树。本仓库目录：

```text
weibo22/events.txt              # eid + label，约 64MB
weibo22/posts/Weibo/<eid>.json  # 4664 棵树
```

盘点（`scripts/weibo22_inventory.json`）：

| 项目 | 数值 |
| --- | --- |
| 级联数 | 4664（非谣言 2351 / 谣言 2313） |
| 节点 / 边 | 约 381 万 / 380 万 |
| 独立用户 | 约 286 万 |
| 单树节点中位数 | 248（最小 10，最大约 5.9 万） |
| 持续时间中位数 | 约 521 小时；3324 棵树跨度 ≥ 7 天 |

与本地 DAMMFND 多模态表（`data/`）**没有实例级对齐**：根 mid 对不上，不能把现成的文本/图像 `pkl` 搬过来。约 1070 条根文本前缀相似，是谣言文案模板，不是同一条微博。

因此本轮只用时序图，不用 DAMMFND 模态。

## 3. 阻断协议

固定随机种子 `3074`。纳入条件：未来节点 ≥ 20，且观察集非空。实际选取 `min(k, |候选|)`。

观察窗口：

- 主设定：`time:1h`、`time:6h`（突发早期）
- 基线表另报了 `time:24h` 以及按到达顺序的 `prefix:20/50`

预算：`k ∈ {1, 5, 10}`。

策略：

| 名称 | 含义 |
| --- | --- |
| random | 观察集均匀抽样 |
| earliest | 最早出现的 k 个非根节点 |
| followers | 粉丝数最大的 k 个 |
| outdegree_obs | 观察窗口内出度最大的 k 个（主基线） |
| greedy_oracle | 反复选还能覆盖最多未覆盖未来节点的观察节点（事后上界，不可部署） |
| tgn | MiniTGN 按预测的未来子树规模取 top-k |

## 4. 非学习基线（全量可评级联）

`scripts/blocking_baseline.py` 在全部可评级联上计算，谣言子集单独汇总。主设定建议看谣言、`k=5`。

谣言树、`k=5`，平均 `block_rate`：

| 窗口 | 随机 | 最早转发 | 粉丝数 | 观察出度 | 贪心上界 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1h | 3.8% | 5.5% | 9.9% | **10.6%** | 15.5% |
| 6h | 3.0% | 4.5% | 11.0% | **13.3%** | 22.9% |
| 24h | 1.9% | 3.4% | 11.6% | **14.9%** | 32.6% |

1 小时窗口约 4203 棵可评级联（谣言 2065）。出度已经明显好于随机，但和 oracle 仍有空档；观察越久，空档越大。TGN 要抢的就是这截空隙。

## 5. MiniTGN

目标：在同一协议上超过观察出度，而不是刷分类准确率。

模型（`scripts/tgn_blocking.py`）：

- 节点特征 3 维：`log1p(粉丝数)`、`log1p(距根小时)`、深度/16
- 按时间回放观察窗口内的转发边，GRU 更新源/目标记忆
- 用记忆 + 特征回归 `log1p(该节点未来子树规模)`，按预测值取 top-k
- 速度限制：每棵树最多回放最近 128 条边；训练只对最后 32 条反传（截断 BPTT）
- 级联级 70/15/15 分层划分（seed=3074）：3264 / 698 / 702
- 训练窗口：1h 与 6h；损失 SmoothL1；5 个 epoch；设备 CUDA

训练经过：2026-09-17 因断电停在第 2 个 epoch（val ≈ 0.0698）；2026-09-19 从该权重续训到第 5 个 epoch。最好验证在 **epoch 3**（SmoothL1 **0.0695**），第 4、5 个 epoch 验证集回升到 0.0697。测试评估加载最好权重。

## 6. 持出谣言树结果

测试集谣言树：1h 可评 311 棵，6h 可评 285 棵。与上一节全量基线**不能逐格对比**。

平均 `block_rate`：

**1 小时**

| 策略 | k=1 | k=5 | k=10 |
| --- | ---: | ---: | ---: |
| 随机 | 1.01% | 3.80% | 5.94% |
| 粉丝数 | 5.64% | 10.60% | 12.12% |
| 观察出度 | 7.53% | 11.19% | 12.23% |
| MiniTGN | 7.58% | 11.33% | 12.71% |
| 贪心 oracle | 10.75% | 16.01% | 17.25% |

**6 小时**

| 策略 | k=1 | k=5 | k=10 |
| --- | ---: | ---: | ---: |
| 随机 | 0.71% | 2.90% | 6.06% |
| 粉丝数 | 7.24% | 12.17% | 15.10% |
| 观察出度 | 9.39% | 14.37% | 16.43% |
| MiniTGN | 9.20% | 13.75% | 16.00% |
| 贪心 oracle | 15.04% | 24.75% | 27.55% |

主设定 1h·k=5：TGN **11.3%**，出度 **11.2%**，oracle **16.0%**。6 小时上 TGN 略低于出度。

## 7. 结论

1. 实现树阻断协议可以跑通，出度是稳定的可部署下界，oracle 说明还有结构空间。
2. **当前 MiniTGN 没有超过观察出度。** 验证损失几乎不动（0.0698 → 0.0695），模型没有学到出度以外的排序信号。
3. 再加同一套结构的 epoch 没有意义。要超过出度，需要改特征、目标函数或边回放，而不是继续训。
4. DAMMFND 多模态与 weibo22 对不齐，本轮结论不依赖它。

## 8. 下一步

- 换学习设定：完整边回放、pairwise / ListMLE 排序、或显式把观察出度当作输入特征。
- 反事实 rollout 仍可按现有协议扩窗口，但学习方法要换一档。
- 多模态与级联对齐继续暂缓。
