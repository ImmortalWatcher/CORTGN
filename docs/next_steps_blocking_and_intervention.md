## 0. 当前基线（成功与否都相对这些数字）

协议不变：`weibo22`，根帖时刻为 0，候选是 \(t_0\) 前已出现的非根节点，阻断 = 切掉该节点在 \(t_0\) 之后的子树。`block_rate` = 被切掉的未来节点 / 全部未来节点。种子 3074。未来节点少于 20 的树不评。

全量谣言树、\(k=5\) 的平均 block_rate：1h 观察出度 10.6%，oracle 15.5%；6h 出度 13.3%，oracle 22.9%。

持出测试集谣言（与全量表不是同一批树）：

| 窗口 | 出度 k=5 | MiniTGN k=5 | oracle k=5 |
| --- | ---: | ---: | ---: |
| 1h（311 棵） | 11.19% | 11.33% | 16.01% |
| 6h（285 棵） | 14.37% | 13.75% | 24.75% |

MiniTGN 在 1h 上只比出度高 0.14 个点，6h 上更低。验证 SmoothL1 从 0.0698 到 0.0695。同一结构继续加 epoch 没有信息量。

主成功线改成测试集谣言、`time:1h`、\(k=5\)：

- 必须报告与观察出度、贪心 oracle 的差。
- 达到线：block_rate ≥ 出度 + 1.0 个绝对点（测试集上即 ≥ 12.2%），并且 `time:6h`、\(k=5\) 不低于该窗口的观察出度。
- 1h 的 oracle 是 16.0%。超过 16% 说明协议被泄漏（用了 \(t_0\) 之后的结构来选节点），结果作废。

## 1. 第一步：在现有树上补 BM 指标（不训练）

VLDB 论文的引理 2：固定预算上的近似，推不出「达到阈值所用人数」的近似。现在只有 IMIN（\(k\in\{1,5,10\}\)）。补 BM。

改 `scripts/blocking_baseline.py`，或新增 `scripts/blocking_bm.py` 复用同一解析函数。

- 阈值用未来节点比例 \(\eta\in\{0.10, 0.15, 0.20\}\)，不是论文里的绝对期望人数。树大小差两个数量级，绝对人数不可比。
- 候选仍是观察窗口内的非根节点。选中 \(v\) 后，把 \(v\) 的观察子树中的其他候选标成冗余，边际增益按「尚未覆盖的未来节点」重算。这是论文 Heur-BM 的边际更新，在树上是精确的，不需要 CP sequence。
- 策略：`outdegree_obs` 的贪心版、`followers` 的贪心版、`greedy_oracle`。oracle 只作上界。
- 输出 `scripts/blocking_bm_results.json`：每组窗口 × \(\eta\) × 策略，报平均 \(\lvert B\rvert\)、达标率、达标时的 block_rate。若候选耗尽仍未达标，\(\lvert B\rvert\) 记为候选人数并记 `met=false`。
- 窗口先跑 `time:1h` 和 `time:6h`，谣言与非谣言分开。

完成标准：一张表能回答「1 小时内要把谣言未来传播压下 10%，出度贪心平均要删几个点，离 oracle 还差几个」。这一步半天到一天，给后面的 RL 提供第二个奖励。

## 2. 第二步：强化学习做序贯阻断（主实验）

把「观察窗口结束时一次性 top-\(k\)」改成「窗口内按到达顺序决定是否花掉一个名额」。一次性 top-\(k\) 会在同一条转发链上重复选祖先和后代；祖先被选中后，后代的未来边际是 0。MiniTGN 回归的是每个点自己的未来子树，没有这个集合效应。

### 2.1 MDP

一条级联一条 episode。先只做 `time:1h`，\(k=5\)，和测试表对齐。

- 状态（每个仍可选的候选一个向量，不能含 \(t_0\) 之后的节点或边）：`log1p(粉丝)`、距根小时、深度、观察出度、是否已有祖先被选、剩余名额、已选人数、该候选相对当前时刻的新近程度。观察出度必须作为输入。上一轮 TGN 没喂这个量，模型要自己从记忆里重建它，结果只是在拟合出度。
- 动作：在当前候选上打分，取得分最高且未被标冗余的一个；或在 BM 模式里允许 STOP。IMIN 模式选满 \(k\) 停止。
- 转移：确定性。选中后将其观察后代标为冗余。
- 奖励：episode 结束给真实 `block_rate`。中间用 oracle 边际做 potential shaping，系数从 1 线性降到 0。状态里始终没有未来节点身份，shaping 只出现在训练奖励里。验证和测试关闭 shaping。
- 划分：沿用 `tgn_blocking.py` 的级联级 70/15/15，种子 3074。测试只评谣言。

### 2.2 算法与实现

新文件 `scripts/rl_blocking.py`。

- 第一版用 REINFORCE，价值基线是同一 batch 的平均回报。动作是对变长候选打分后 softmax。网络用两层 MLP，隐藏维 64，输入就是上面的特征向量。先不要接 MiniTGN 的 GRU。若 MLP 已经超过出度，再把 GRU 记忆接回去做消融。
- 对照必须同时跑，写进同一个 json：`random`、`outdegree_obs`、`greedy_oracle`、MLP 回归未来子树再 top-\(k\)（ListMLE 或 pairwise hinge，二选一）、REINFORCE。回归对照用来区分「换了排序损失就够」和「必须序贯决策」。
- 训练预算：最多 20 个 epoch，按验证集谣言 block_rate 早停，连续 3 个 epoch 不升就停。日志写 `scripts/rl_blocking_train.log`，结果写 `scripts/rl_blocking_results.json`。
- 设备沿用现有 CUDA 路径。每棵树只编码观察窗口内的候选，不做 128 条边的截断 BPTT。

### 2.3 消融（主结果出来之后再跑）

- 去掉 shaping。
- 去掉「祖先已被选」标记。
- 去掉观察出度特征。

三份消融都要在同一测试集上给出 1h 与 6h 的 \(k=5\)。6h 用 1h 训出的策略直接评，另做一版在 6h 上重训。若只有重训才不低于出度，要在报告里写明策略没有跨窗口迁移。

## 3. 第三步：内容干预只做小样本，且受检测置信度约束

ED2D 说明：判对时辩论记录的说服接近 Snopes 编辑，假说法转发意愿下降；判错时相信和转发上升，和正确解释同时出现也只能部分抵消。Weibo21 上 ED2D Acc 83.59，相对无证据的 D2D 只高 1.42 个点。本仓库文本轮次 AUC 约 0.53–0.56。

因此内容线的顺序是：

1. **先算净伤害阈值，再决定要不要生成文本。** 用 ED2D Table 3 的假说法 Belief 变化做数量级估计：判对时 Belief 3.46→2.85（下降 0.61），判错时 3.80→4.44（上升 0.64）。设检测准确率 \(p\)、假说法占比按 Snopes25 的 \(252/448\) 只作外推参考，微博上用 weibo22 谣言比例 2313/4664。在「只对判定为谣言的根帖发辟谣」的策略下，写一个 20 行的脚本 `scripts/debunk_harm_threshold.py`，扫 \(p\in[0.5,0.95]\)，输出 Belief 期望变化由负转正的 \(p\)。这是上线条件，不是用户实验。
2. **样本。** 从测试集谣言里取 1h、\(k=5\)、出度 block_rate 最低的 30 棵和最高的 30 棵。只用根帖 `text`（JSON 里已有 `text` 与 `original_text`）。不跑 2313 条，不调用 8 智能体。
3. **最小辩论。** 正方 1、反方 1、法官 1、自由辩论 1 轮、实体最多 5 个。检索先用本地能访问的中文维基或搜索接口；没有可用检索时，这一步停在「实体列表 + 模型内部论点」，并在结果里标记 `evidence=none`。ED2D 的增益依赖外部证据，没有证据的跑法只能当作 D2D 的弱化版，不能写成复现 ED2D。
4. **自动检查，替代暂时做不了的 200 人实验。** 对每条输出记录：预测标签、是否与 weibo22 的 `label` 一致、引用段落是否包含与根帖实体重叠的句子、法官五维分数。一致率低于第 1 步算出的阈值时，不把解释发到任何「干预」结论里。
5. **和阻断的接点。** RL 或出度选出的节点集合，记为「若做内容干预，解释应投放的转发账号」。投放不改变 `block_rate`。报告里路径表和内容表分开。在没有真人 Likert 之前，内容表只报检测一致率和证据重叠，不报「说服提升」。

DAMMFND 多模态与 weibo22 仍不对齐。检测门控在对齐完成前用 weibo22 自带标签做离线分析；对齐是独立任务，不放进这一轮。

## 4. 第四步：仅当需要和 VLDB 算法直接对比时

把用户在多棵树之间的转发收成有向图（盘点约 286 万独立用户），\(p(u,v)=1/\mathrm{in\text{-}degree}(v)\)，种子用谣言根用户。调用 https://github.com/jhwang0116/IMIN_BM 的 Heur-IMIN 与 App-BM+，不在本仓库重写 CP-Gen、LRR 和鞅停止条件。

这张表的指标是论文的 \(D(B)\) 或 \(\lvert B\rvert\)，与树协议 `block_rate` 分开保存，例如 `scripts/user_graph_imin_results.json`。微博树是单父节点，\(D_L=D=D_U\)，在单棵树上重写 SandIMIN 没有算法收益。
